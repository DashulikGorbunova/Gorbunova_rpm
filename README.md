# Лабораторная работа №1: индексы PostgreSQL

Учебный сервис заказов создан с нуля для этой работы: исходный репозиторий был пустым. Используются Python 3.12+ (без сторонних пакетов), Docker и PostgreSQL 17. Это учебный адаптер через `docker exec psql`, не production-архитектура.

## Запуск

Из корня репозитория:

```bash
bash scripts/start-db.sh
python scripts/migrate.py
python scripts/server.py
```

Сервис слушает `127.0.0.1:8080`. Запросы: `GET /health`, `GET /users/123/orders?status=PAID&days=30&limit=50`. `status` и `days` необязательны, `limit` по умолчанию 20 (1–100). Сортировка: `created_at DESC, id DESC`. Неверные параметры возвращают 400. База по умолчанию пустая; демонстрационные данные загружаются отдельно.

PostgreSQL не публикует порты на хост; trust-аутентификация допустима только для этой изолированной учебной базы. Не подключайте к ней недоверенные контейнеры. Имя контейнера можно изменить через `PG_CONTAINER`.

## Воспроизведение всех измерений с чистого состояния

Используйте **новый выделенный контейнер**. Не удаляйте чужие базы. Скрипт экспериментов пересоздаёт только схему `lab`; сервисный эксперимент требует пустую таблицу и миграцию только версии 001.

```bash
export PG_CONTAINER=rpm-lab-replay
bash scripts/start-db.sh
python scripts/experiments.py
python scripts/service_experiments.py
python scripts/smoke.py
python scripts/report.py
```

Не запускайте `migrate.py` без аргумента перед сервисными измерениями: индексная миграция должна примениться между замерами. Для обычной разработки `python scripts/migrate.py` применяет обе миграции и безопасен при повторном запуске. Скрипты измерений сохраняют JSON-планы в `docs/plans/`. Повторный запуск меняет замеры и время генерации данных; миллисекунды не являются фиксированным нормативом.

[Отчёт](docs/lab-01-indexes.md). SQL подготовки: `sql/01-seed.sql`. Миграции: `migrations/001_orders.sql` и `migrations/002_indexes.sql`. Для проверок наполненной базы: `python scripts/smoke.py` (свободный порт 8080).
